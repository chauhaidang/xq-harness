01 · XQ KRAKEN
Open with the promise, not the implementation. Kraken makes a large OpenAPI contract usable as a small sequence of safe decisions.
The friction

Agents can read an API.
That does not mean they can use it safely.

01 / TOO MUCH CONTEXT

Whole specifications are noisy

An agent rarely needs every path, schema, response, and component for one decision.

02 / TOO LITTLE POLICY

OpenAPI describes, not permits

Visibility and call permissions need a product-level allowlist applied everywhere.

03 / BRITTLE CHAINING

Copying values invites drift

Multi-step flows need durable, typed references—not text scraping and guesswork.

02 · THE FRICTION

Live demo · Chain

Pass values by reference.
Keep their JSON types intact.

get.json
{
  "parameters": {
    "widgetId": {
      "$kraken_ref": "@r1",
      "pointer": "/id"
    }
  }
}
What Kraken does
Resolves /id from the immutable @r1 snapshot
Preserves the stored JSON type
Validates the resulting request against OpenAPI
Invokes GET /widgets/widget-123
$ kraken invoke @o2 --input get.json --pretty

10 · CHAIN
This explicit reference object avoids interpreting ordinary strings beginning with @ as state. Follow with `kraken resolve @r1 --pointer /id` if you want to show direct inspection.
Guardrails

Determinism is a feature,
not an implementation detail.

01

Policy stays aligned

Search, describe, and invoke enforce the same operation allowlist.

02

Failures are actionable

Stable exit categories separate input, contract, transport, and assertion failures.

03

State cannot drift

References never rebind; config and spec changes fail before transport.

JSON by default --pretty for humans --no-state for sensitive calls 24h response retention
